## 三、步骤 2：逐个验证 API 接口

使用 PowerShell 的 `Invoke-RestMethod` 逐个测试所有 9 个 API 接口。

### 接口 1：`GET /api/students/` — 获取学生列表

**请求**：
```powershell
Invoke-RestMethod -Uri "http://localhost:5000/api/students/" -Method Get | ConvertTo-Json -Depth 5
```

**响应**（200 OK）：
```json
{
    "data": [
        {
            "student_id": "STU_F_0001",
            "student_name": "Student_F_1",
            "student_gender": "M",
            "student_age": null,
            "student_address": null,
            "student_class_id": "CLS003"
        }
        // ... 共 20 条（默认分页）
    ],
    "total": 7655,
    "page": 1,
    "per_page": 20
}
```

**验证结果**：通过。返回分页数据，total=7655，默认每页 20 条。

## 四、步骤 3：问题排查与修复

### 排查过程

对所有接口逐一检查以下方面：

1. **SQL 语法**：所有 SQL 语句语法正确，无报错
2. **表名/字段名**：与建表脚本一致，查询正常
3. **数据库连接**：连接正常，数据可正常读取
4. **import 路径**：所有模块导入路径正确，无 ModuleNotFoundError

### 发现的问题

**无**。所有 9 个接口均返回 200 状态码，JSON 数据格式正确，无 null 异常。

### 注意事项

- `risk_alert` 和 `learning_suggestion` 表当前为空，这是预期行为，因为 AI 功能（阶段七）尚未开发
- `high_risk_count` 返回 0 是正常的，待 AI 风险预警功能开发后会自动有数据
- 部分学生的 `student_age`、`student_address`、`score_date` 字段为 null，这是数据导入时的原始状态，不影响接口功能
