## 二、开发步骤

### 步骤 1：在 `backend/routes/score.py` 中添加 `/overview` 学情概览接口

**实现接口**：

| 路由 | 方法 | 功能 | 返回字段 |
|------|------|------|----------|
| `/overview` | GET | 学情概览 | `total_students`、`average_score`、`high_risk_count` |

**关键代码**：
```python
@score_bp.route('/overview', methods=['GET'])
def get_overview():
    """学情概览：学生总数、G3平均成绩、高风险预警人数"""
    total_result = query_one("SELECT COUNT(*) AS total_students FROM student")
    avg_result = query_one(
        "SELECT ROUND(AVG(score), 2) AS average_score FROM exam_score WHERE exam_stage = 'G3'"
    )
    risk_result = query_one(
        "SELECT COUNT(*) AS high_risk_count FROM risk_alert WHERE risk_level = 'high'"
    )

    return jsonify({
        'total_students': total_result['total_students'] if total_result else 0,
        'average_score': avg_result['average_score'] if avg_result else 0,
        'high_risk_count': risk_result['high_risk_count'] if risk_result else 0
    })
```

**设计说明**：
- 三条独立 SQL 分别查询学生总数、G3 阶段平均成绩、高风险预警人数
- 使用 `ROUND(AVG(score), 2)` 保留两位小数
- 高风险预警人数从 `risk_alert` 表查询 `risk_level = 'high'` 的记录数
- 当前预警尚未生成，`high_risk_count` 为 0，后续 7.3 步骤实现预警生成后会有数据
- 对查询结果做 None 兜底处理，避免空表时返回 null

### 步骤 2：在 `backend/routes/score.py` 中添加 `/distribution` 成绩分布接口

**实现接口**：

| 路由 | 方法 | 功能 | 参数 |
|------|------|------|------|
| `/distribution` | GET | 成绩分布统计 | `subject_id`（可选）、`exam_stage`（默认 G3） |

**关键代码**：
```python
@score_bp.route('/distribution', methods=['GET'])
def get_distribution():
    """成绩分布：按区间统计人数，支持按科目和考试阶段筛选"""
    subject_id = request.args.get('subject_id', '')
    exam_stage = request.args.get('exam_stage', 'G3')

    # 根据科目判断分制：SUBJ_GENERAL 为百分制，其余为二十分制
    if subject_id == 'SUBJ_GENERAL':
        bins_sql = """
            CASE
                WHEN score BETWEEN 0 AND 19 THEN '0-19'
                WHEN score BETWEEN 20 AND 39 THEN '20-39'
                WHEN score BETWEEN 40 AND 59 THEN '40-59'
                WHEN score BETWEEN 60 AND 79 THEN '60-79'
                WHEN score BETWEEN 80 AND 100 THEN '80-100'
            END
        """
    else:
        bins_sql = """
            CASE
                WHEN score BETWEEN 0 AND 4 THEN '0-4'
                WHEN score BETWEEN 5 AND 9 THEN '5-9'
                WHEN score BETWEEN 10 AND 14 THEN '10-14'
                WHEN score BETWEEN 15 AND 20 THEN '15-20'
            END
        """

    sql = (
        f"SELECT {bins_sql} AS score_range, COUNT(*) AS count "
        f"FROM exam_score WHERE exam_stage = %s "
    )
    params = [exam_stage]

    if subject_id:
        sql += "AND subject_id = %s "
        params.append(subject_id)

    sql += f"GROUP BY score_range ORDER BY score_range"

    distribution = query_all(sql, params)

    # 确保所有区间都有数据（补零）
    if subject_id == 'SUBJ_GENERAL':
        default_ranges = ['0-19', '20-39', '40-59', '60-79', '80-100']
    else:
        default_ranges = ['0-4', '5-9', '10-14', '15-20']

    result_map = {item['score_range']: item['count'] for item in distribution if item['score_range']}
    result = [{'score_range': r, 'count': result_map.get(r, 0)} for r in default_ranges]

    return jsonify(result)
```

**设计说明**：
- **自适应分制**：数据库中存在两种分制的成绩数据——UCI 数据集（SUBJ_MATH、SUBJ_PORTUGUESE）为 0-20 分制，Performance Factors 数据集（SUBJ_GENERAL）为 0-100 分制。根据 `subject_id` 参数自动选择合适的区间划分：
  - 二十分制区间：0-4、5-9、10-14、15-20
  - 百分制区间：0-19、20-39、40-59、60-79、80-100
- **不指定科目时**：默认使用二十分制区间（因为二十分制科目数量更多）
- **区间补零**：SQL GROUP BY 可能跳过空区间，通过 `default_ranges` 列表补零，确保前端图表连续显示
- **动态 SQL**：`subject_id` 为可选参数，存在时添加 WHERE 条件，使用参数化查询防止 SQL 注入
- **f-string 安全性**：`bins_sql` 由服务端逻辑硬编码生成，不接受用户输入，不存在注入风险

### 步骤 3：在 `backend/routes/student.py` 中添加 `/search` 搜索接口

**实现接口**：

| 路由 | 方法 | 功能 | 参数 |
|------|------|------|------|
| `/search` | GET | 按姓名模糊搜索学生 | `keyword`（搜索关键词） |

**关键代码**：
```python
@student_bp.route('/search', methods=['GET'])
def search_students():
    """按姓名模糊搜索学生"""
    keyword = request.args.get('keyword', '')
    if not keyword:
        return jsonify({'data': [], 'total': 0})
    students = query_all(
        "SELECT * FROM student WHERE student_name LIKE %s LIMIT 20",
        (f'%{keyword}%',)
    )
    return jsonify({'data': students, 'total': len(students)})
```

**设计说明**：
- 使用 `LIKE '%keyword%'` 实现模糊搜索，匹配姓名中任意位置包含关键词的学生
- 空关键词直接返回空列表，避免全表扫描
- `LIMIT 20` 限制返回数量，防止大量结果影响性能
- 返回格式与 `/api/students/` 列表接口一致（`{ data, total }`），便于前端复用组件
- 使用参数化查询（`%s` + 元组），防止 SQL 注入

**注意**：`/search` 路由必须注册在 `/<student_id>` 之前，否则 `search` 会被当作 `student_id` 参数匹配。Flask 按注册顺序匹配路由，当前代码已确保顺序正确。

## 五、技术要点总结

1. **自适应分制**：distribution 接口根据 `subject_id` 自动切换二十分制/百分制区间，解决多数据集混合分制问题
2. **区间补零**：SQL GROUP BY 可能跳过空区间，通过预设 `default_ranges` 列表补零，保证前端图表数据连续
3. **路由注册顺序**：`/search` 必须在 `/<student_id>` 之前注册，否则 `search` 字符串会被当作路径参数捕获
4. **空参数防护**：search 接口空关键词直接返回空列表，避免无意义的全表扫描
5. **参数化查询**：所有 SQL 均使用 `%s` 占位符 + 参数元组，防止 SQL 注入
6. **f-string 安全性**：distribution 中的 `bins_sql` 由服务端硬编码逻辑生成，不接受用户输入，无注入风险
