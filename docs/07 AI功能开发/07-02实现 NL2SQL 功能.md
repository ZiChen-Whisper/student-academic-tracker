## 一、开发步骤

### 步骤 1：创建 `backend/services/nl2sql_service.py`

这是 NL2SQL 的核心服务文件，包含以下四个核心组件：

#### 1.1 DDL_SCHEMA 常量

将建表脚本中 12 张表的 `CREATE TABLE` 语句作为字符串常量，供 Prompt 使用。包含：
- teacher（教师表）
- subject（科目表）
- class（班级表）
- student（学生表）
- exam_score（考试成绩表）
- learning_behavior（学习行为表）
- family_background（家庭背景表）
- risk_alert（风险预警表）
- learning_suggestion（学习建议表）
- course_schedule（课程安排表）
- student_subject（学生科目选修表）
- nl2sql_log（NL2SQL查询日志表）

#### 1.2 SYSTEM_PROMPT 常量

系统提示词设计包含以下关键部分：

1. **角色定义**：SQL 专家，将自然语言转为 MySQL SQL
2. **数据库表结构**：完整的 12 张表 DDL
3. **数据集说明**：
   - UCI Math 数据集（STU_M_ 前缀，397名学生，0-20分制，及格线10分）
   - UCI Portuguese 数据集（STU_P_ 前缀，651名学生，0-20分制，及格线10分）
   - Performance Factors 数据集（STU_F_ 前缀，6607名学生，0-100分制，及格线60分）
4. **关键字段说明**：枚举值、格式规范等
5. **重要规则**：只允许 SELECT、区分分制、中文别名等
6. **Few-shot 示例**：4 个自然语言→SQL 配对示例

#### 1.3 `nl2sql(question)` 函数

核心流程：
1. 调用 DeepSeek API，将自然语言问题转为 SQL
2. 清理返回的 SQL（去除 markdown 代码块标记、末尾分号）
3. 安全检查（只允许 SELECT 查询，禁止写操作）
4. 执行生成的 SQL，返回结果
5. 记录查询日志到 `nl2sql_log` 表
6. 返回格式：`{ sql, result, error, execution_time_ms }`

#### 1.4 `log_nl2sql()` 函数

将查询记录插入 `nl2sql_log` 表，包含自然语言输入、生成的SQL、执行耗时、是否正确等信息。

## 三、关键设计决策

### 3.1 Prompt 设计策略

1. **完整的 DDL Schema**：将 12 张表的完整建表语句放入 Prompt，让 LLM 准确理解表结构和外键关系
2. **数据集说明**：明确区分三个数据集的分制差异（0-20 vs 0-100），避免 LLM 混淆及格线
3. **Few-shot 示例**：提供 4 个典型查询示例，引导 LLM 生成规范的 SQL
4. **中文别名规则**：要求使用中文 AS 别名，使查询结果更易读

### 3.2 安全措施

1. **SQL 安全校验**：`_is_safe_sql()` 函数检查生成的 SQL 是否以 SELECT 开头，是否包含写操作关键字
2. **SQL 清理**：`_clean_sql()` 函数去除 markdown 代码块标记和末尾分号
3. **异常处理**：所有数据库操作都有 try-except 保护，日志写入失败不影响主流程

### 3.3 日志记录

每次查询都记录到 `nl2sql_log` 表，便于：
- 追踪查询历史
- 统计准确率
- 分析失败原因
- 优化 Prompt
