## 一、开发步骤

### 步骤 1：创建 `backend/services/risk_service.py`

这是风险预警的核心服务文件，包含以下三个核心组件：

#### 1.1 `predict_risk(student_data)` 函数

基于规则的学生风险评分函数，综合评估多个维度：

**风险评分规则**：

| 评估维度 | 条件 | 加分 |
|---------|------|------|
| 平均成绩（0-20分制） | < 10 分 | +3 |
| 平均成绩（0-20分制） | 10-14 分 | +1 |
| 平均成绩（0-100分制） | < 60 分 | +3 |
| 平均成绩（0-100分制） | 60-74 分 | +1 |
| 出勤率 | < 80% | +2 |
| 动机水平 | Low | +2 |
| 动机水平 | Medium | +1 |

**风险等级划分**：

| 风险评分 | 等级 |
|---------|------|
| ≥ 5 | high |
| ≥ 3 | medium |
| < 3 | low |

**关键设计决策**：
- 支持两种分制（0-20 和 0-100），根据 `student_id` 前缀自动判断
- STU_F_ 前缀学生使用 0-100 分制，STU_M_/STU_P_ 使用 0-20 分制
- 出勤率和动机水平为可选因素，缺失时不加分（不影响评分）
- 返回结果包含 `features` 列表，记录触发风险的具体因素

#### 1.2 `calculate_risk_for_all()` 函数

批量计算所有学生风险的函数，流程如下：

1. 清空 `risk_alert` 表中的旧预警数据
2. 查询所有学生的 G3 平均成绩（`SELECT student_id, AVG(score) FROM exam_score WHERE exam_stage='G3' GROUP BY student_id`）
3. 查询学习行为数据（出勤率、动机水平）
4. 构建 `behavior_map` 字典，以 `student_id` 为键快速查找
5. 对每个学生调用 `predict_risk` 计算风险
6. 调用 `save_alert` 将结果保存到 `risk_alert` 表
7. 返回预警列表

**数据分布特点**：
- `learning_behavior` 表只有 STU_F_ 前缀的学生数据（6607 条）
- STU_M_（397名）和 STU_P_（651名）学生没有学习行为数据
- 因此 STU_M_/STU_P_ 学生的风险评分仅基于成绩

#### 1.3 `save_alert(risk_info)` 函数

将预警信息插入 `risk_alert` 表：
- `risk_factors` 字段使用 JSON 格式存储，包含触发风险的具体因素列表
- `alert_time` 使用当前时间
- `intervention_status` 默认为 `pending`

### 步骤 2：更新 `backend/routes/alert.py`

实现以下 5 个 API 接口：

| 路由 | 方法 | 功能 | 参数 |
|------|------|------|------|
| `/` | GET | 查询预警列表 | 可选 `risk_level` 筛选 |
| `/generate` | POST | 为所有学生重新生成预警 | 无 |
| `/<alert_id>/intervene` | PUT | 更新干预状态和措施 | JSON: `intervention_status`, `intervention_measure` |
| `/stats` | GET | 预警统计（按风险等级分组计数） | 无 |
| `/train-model` | POST | 训练 ML 风险预警模型 | 无 |

**接口详细说明**：

1. **GET `/`**：支持 `risk_level` 查询参数筛选，按 `alert_time` 降序排列
2. **POST `/generate`**：调用 `calculate_risk_for_all()`，返回生成统计信息
3. **PUT `/<alert_id>/intervene`**：验证 `intervention_status` 必须为 `pending/in_progress/completed`，检查预警 ID 是否存在
4. **GET `/stats`**：返回 `{"high": N, "medium": N, "low": N}` 格式的统计数据
5. **POST `/train-model`**：调用 `train_risk_model()`，返回模型评估结果

### 步骤 3：实现 ML 模型预警（可选功能）

在 `risk_service.py` 中添加 `train_risk_model()` 函数：

**模型配置**：
- 算法：RandomForestClassifier（100 棵决策树）
- 特征：student_age, attendance_rate, study_hours, sleep_hours, tutoring_sessions, motivation_num
- 标签：根据 G3 平均成绩划分（<60 high, <75 medium, else low）
- 数据集：仅使用 STU_F_ 学生（有完整的学习行为数据）
- 训练/测试划分：80%/20%，stratified split

**特征重要性排序**：
1. study_hours（0.405）— 学习时长最重要
2. attendance_rate（0.298）— 出勤率次之
3. sleep_hours（0.121）— 睡眠时长
4. tutoring_sessions（0.118）— 辅导次数
5. motivation_num（0.058）— 动机水平
6. student_age（0.000）— 年龄无影响

## 三、关键设计决策

### 3.1 双分制支持

由于项目包含三个数据集，成绩分制不同：
- STU_M_ 和 STU_P_：0-20 分制，及格线 10 分
- STU_F_：0-100 分制，及格线 60 分

风险评分规则根据 `student_id` 前缀自动选择对应的分制阈值，确保不同数据集的学生都能被合理评估。

### 3.2 多因素综合评估

基于规则的预警不仅看成绩，还综合了出勤率和动机水平。这使得：
- 成绩中等但出勤率低且动机低的学生会被评为高风险
- 成绩偏低但其他方面良好的学生被评为中风险
- 评估结果比单纯看成绩更全面

### 3.3 缺失数据优雅处理

STU_M_ 和 STU_P_ 学生没有学习行为数据，`predict_risk` 函数对缺失的出勤率和动机水平不做加分处理，仅基于成绩评分。这是合理的，因为缺失数据不应被默认为风险因素。

### 3.4 ML 模型特征重要性

ML 模型的特征重要性分析显示：
- **study_hours（学习时长）** 是最重要的预测特征（40.5%）
- **attendance_rate（出勤率）** 次之（29.8%）
- **student_age（年龄）** 对风险预测无影响（0%）

这与教育学研究结论一致：学习投入时间是学业成绩的最强预测因子。

### 3.5 SQL 兼容性

`train_risk_model()` 中的 SQL 查询需要兼容 MySQL 的 `only_full_group_by` 模式，所有非聚合列都包含在 `GROUP BY` 子句中。

## 四、已知限制

1. **STU_M_/STU_P_ 学生预警精度较低**：由于缺少学习行为数据，这些学生的风险评分仅基于成绩，无法综合评估出勤率和动机
2. **ML 模型类别不均衡**：high 和 low 类别的样本远少于 medium，导致这两个类别的 recall 较低
3. **Flask debug 模式与 sklearn 冲突**：导入 sklearn 时会触发 numpy/scipy 的 `__config__.py` 变化，导致 Flask watchdog 反复重启服务器。生产环境应关闭 debug 模式
